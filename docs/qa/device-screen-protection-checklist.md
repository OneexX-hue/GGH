# Чеклист: защита экрана на реальных устройствах

> ⚠️ **Ничего в этом файле не было прогнано на реальном устройстве.**
> `react-native-capture-protection` подключён и вызывается из
> `mobile/src/media/ProtectedMediaViewer.tsx` (см. код и комментарий
> там же), но эта сессия — управляемая облачная песочница без телефона,
> физического планшета или полноценного эмулятора с нативной сборкой
> Expo Dev Client. Всё, что можно было сделать без устройства
> (типизация, `tsc --noEmit`, юнит-тесты чистой логики, чтение
> документации библиотеки и сверка вызовов API) — сделано; сам факт
> «действительно ли ОС блокирует скриншот» — нет. Использовать этот
> чеклист перед первым продакшен-релизом, отмечая реальные результаты.

## Зачем это разделено на Android/iOS/Web

Как подробно объяснено в `docs/TZ.md` (глава 3.3), полный технический
запрет скриншота существует **только на Android**. На iOS и Web
физически невозможно предотвратить фотографирование экрана — там
работает только детекция постфактум + водяной знак + журнал доступа.
Чеклист ниже проверяет именно то, что реализация делает то, что
**обещано** (не больше и не меньше).

## Как подготовить билд для теста

`expo start --dev-client` через Expo Go **не подходит** —
`react-native-capture-protection` требует нативных модулей. Нужен
кастомный Dev Client или полноценный `eas build --profile preview`
(см. `mobile/eas.json`, README раздел «Публикация в TestFlight/Google
Play»).

## Android (проверить минимум на 2 устройствах/версиях ОС)

| # | Проверка | Ожидаемый результат | Устройство/ОС | Результат | Дата |
|---|---|---|---|---|---|
| A1 | Открыть защищённый просмотрщик фото (`ProtectedMediaViewer`) в чате | Экран отображается нормально | | ☐ Пройдено ☐ Не пройдено | |
| A2 | Попытаться сделать системный скриншот (кнопки громкость−/питание) во время просмотра | Системный скриншот **не создаётся**, либо приложение показывает чёрный/пустой кадр (`FLAG_SECURE`) | | ☐ | |
| A3 | Попытаться запустить запись экрана ОС во время просмотра | Запись либо не стартует, либо записывает чёрный экран в момент показа защищённого медиа | | ☐ | |
| A4 | Проверить `MediaAccessLog` в web-admin (`/audit-log` или напрямую в БД) после A2 | Записи `SCREENSHOT_DETECTED` **не появляется** — на Android скриншот блокируется до того, как event долетает (см. комментарий в коде) | | ☐ | |
| A5 | Закрыть просмотрщик (уйти с экрана) | `CaptureProtection.allow(...)` вызывается — скриншоты вне защищённого экрана снова работают нормально | | ☐ | |
| A6 | Проверить поведение при отсутствии разрешения/недоступности API (если применимо на конкретной прошивке/OEM-сборке — некоторые китайские вендоры режут `FLAG_SECURE`) | Приложение не падает — просмотр продолжает работать, в логах предупреждение (см. `catch` в `ProtectedMediaViewer.tsx`) | | ☐ | |

## iOS (проверить минимум на 2 устройствах/версиях iOS)

| # | Проверка | Ожидаемый результат | Устройство/ОС | Результат | Дата |
|---|---|---|---|---|---|
| I1 | Открыть защищённый просмотрщик фото в чате | Экран отображается нормально | | ☐ | |
| I2 | Сделать системный скриншот во время просмотра | Скриншот **создаётся** (это физически неизбежно на iOS — не баг) | | ☐ | |
| I3 | Проверить `MediaAccessLog` после I2 | Появляется запись `SCREENSHOT_DETECTED` с `metadata.platform: "ios"` в разумное время (секунды) после скриншота | | ☐ | |
| I4 | Запустить запись экрана (Control Center) во время просмотра | Запись создаётся (ожидаемо — iOS не даёт блокировать запись программно); при возможности проверить, ловит ли `UIScreen.capturedDidChangeNotification` начало записи и логирует ли это тоже | | ☐ | |
| I5 | Убедиться, что пользователю **не обещано** «скриншот невозможен» нигде в UI/копирайтинге приложения — только «отслеживается» | Формулировки в приложении соответствуют `docs/TZ.md` гл. 3.3 (честные границы) | | ☐ | |

## Общие проверки (все платформы)

| # | Проверка | Ожидаемый результат | Результат | Дата |
|---|---|---|---|---|
| G1 | Водяной знак на фото содержит опознаваемый ID/псевдоним просматривающего | Водяной знак виден и читаем на изображении (сервер, `sharp`) | ☐ | |
| G2 | Токен доступа к медиа истекает и не может быть переиспользован после истечения | Повторный запрос с истёкшим токеном → `401`/`403`, не отдаёт файл | ☐ | |
| G3 | Журнал доступа (`MediaAccessLog`) фиксирует обычные открытия (не только скриншоты) | Каждое открытие защищённого медиа создаёт запись | ☐ | |

  что-то не прошло) к каждой проваленной строке.

  формулировку «непроверено на реальном устройстве», если весь чеклист
  пройден.
- Если какая-то проверка не прошла — завести отдельную задачу, не
  считать защиту медиа готовой к продакшену до исправления.
